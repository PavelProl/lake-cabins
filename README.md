# lake-cabins — «Домики у озера»

Сайт реальной загородной базы отдыха у озера в Красноярском крае. «Домики у озера» — временное название.

Главная бизнес-цель — обращения потенциальных гостей. Основное действие — звонок владельцу, дополнительное — сообщение в WhatsApp.

## Текущее состояние

Согласована основа первой публичной версии: представление базы, три типа домов с детальными страницами, территория, маршрут и контакты. Подтверждённые сведения и открытые вопросы собраны в продуктовом брифе.

Реализован экспериментальный React-прототип перехода «карточка дома → детальная страница → обратно», визуально ориентированный на North2. Одна карточка большого дома, анимация GSAP Flip и галерея из четырёх предоставленных фотографий. Сгенерированная обложка обозначена как концепция. Разработчик принял визуал; независимое техническое ревью завершено, подтверждённые дефекты исправлены и повторно проверены. Прототип подготовлен к первому PR с кодом. Это основа для дальнейшей работы, а не готовая публичная версия.

Бэкенд, база данных и хостинг не выбраны. Прототип запускается локально и содержит запрет индексирования; это не опубликованный сайт.

Онлайн-бронирование, личные кабинеты, формы заявок и административная панель не входят в первую публичную версию. Дату запуска определим после проверки прототипа и оценки оставшегося объёма.

## Локальный запуск

Требуется Node.js 22.22+ в ветке 22 либо Node.js 24+; проверки выполнены на Node.js 26.4.0. Минимум определяется React Router, ветку 23 не поддерживает ESLint. Установите зависимости и запустите приложение:

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Прямой URL дома: `/houses/large-log-house`.

Проверки: `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. Браузерные сценарии: `npm run test:e2e` (требуется установленный Google Chrome); сборка доступна через `npm run preview`.

## Ограничения прототипа и проверок

Браузерные проверки используют Google Chrome на широком экране и эмуляцию Pixel 7; реальные телефоны, Safari и Firefox пока не проверены. Для установки тестовых браузеров проект ничего автоматически не скачивает. Прямая ссылка работает в Vite dev/preview; правила отдачи SPA на будущем хостинге ещё не выбраны. Способ формирования индексируемых страниц публичной версии предстоит согласовать.

В проверенном наборе зависимостей `npm audit` от 08.11.2026 сообщает об одной moderate-уязвимости `minimatch` ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)), затрагивающей 10 пакетов инструментов ESLint/TypeScript ESLint. Она связана с отказом в обслуживании при обработке glob-шаблонов; high/critical не обнаружены. Автоматическая смена основных версий инструментов не выполнялась. Ограничение нужно пересмотреть при обновлении зависимостей; оно не относится к браузерному коду прототипа.

## Ближайшие этапы

1. Завершить Git-цикл технической приёмки: согласовать коммит, push и первый PR с кодом, затем merge.
2. Проверить плавное раскрытие фотографии в полноэкранную галерею как отдельную задачу; подтвердить материалы владельцев.
3. После визуальной приёмки собрать сайт, включая базовую подготовку к SEO.
4. Опубликовать сайт, проверить индексирование и провести небольшие эксперименты по привлечению гостей: сначала проверить бесплатные размещения и пробные предложения Яндекса и аналогов. Их доступность и условия ещё не исследованы; платный бюджет не согласован.
